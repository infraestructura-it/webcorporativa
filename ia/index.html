Comunicación Modbus TCP con Inversores Fronius Symo: Registros y Configuración

Configuración completa de comunicación Modbus TCP con inversores Fronius Symo, incluyendo registros críticos y código Python

Los inversores Fronius Symo integran comunicación Modbus TCP nativa, facilitando la integración con sistemas SCADA en instalaciones solares comerciales colombianas. La configuración requiere habilitación del protocolo en Fronius Solar.web y configuración de red adecuada.

Configuración de Red:

  • Puerto TCP: 502 (estándar Modbus)
  • Unit ID: 1 (configurable vía interfaz web)
  • Timeout: 5000ms recomendado
  • IP estática obligatoria para monitoreo confiable

Registros Modbus Críticos:

  • 40084-40085: Potencia AC Total (32-bit, Factor: 1W)
  • 40092-40093: Corriente AC Total (32-bit, Factor: 0.01A)
  • 40098-40099: Tensión AC L1-N (32-bit, Factor: 0.01V)
  • 40106-40107: Frecuencia AC (32-bit, Factor: 0.01Hz)
  • 40284-40285: Energía Total DC (32-bit, Factor: 1Wh)
  • 40320: Estado del Inversor (16-bit)

Implementación Python:

from pymodbus.client.sync import ModbusTcpClient

client = ModbusTcpClient('192.168.1.100', port=502)
client.connect()

# Leer potencia AC total (registros 40084-40085)
result = client.read_holding_registers(40084, 2, unit=1)
if result.isError():
print('Error de comunicación')
else:
power_raw = (result.registers[0] << 16) + result.registers[1]
power_w = power_raw if power_raw < 2147483648 else power_raw - 4294967296
print(f'Potencia AC: {power_w}W')

client.close()

La implementación debe considerar valores con signo de 32 bits y manejo de errores de red. Para instalaciones críticas, implementar reconexión automática y logging de fallos de comunicación.

Conectar Fronius Symo a Node-RED usando su API nativa /solar_api/v1/

Integra datos en tiempo real de tu inversor Fronius Symo (potencia, energía, tensiones) en dashboard Node-RED personalizado

El Fronius Symo expone una API REST nativa que permite obtener datos del inversor sin configuraciones complejas. Este tutorial funciona con modelos Symo 3.7-3 hasta Symo 24.0-3.

  1. Instala el nodo node-red-node-http-request desde la paleta de Node-RED
  2. Crea un nodo inject configurado para ejecutar cada 30 segundos
  3. Añade un nodo http request con URL: http://[IP_FRONIUS]/solar_api/v1/GetInverterRealtimeData.cgi?Scope=Device&DeviceId=1&DataCollection=CommonInverterData
  4. Agrega un nodo json para parsear la respuesta
  5. Inserta un nodo function con este código:
    msg.payload = {
      potencia: msg.payload.Body.Data.PAC.Value,
      energia_dia: msg.payload.Body.Data.DAY_ENERGY.Value,
      voltaje_dc: msg.payload.Body.Data.UDC.Value,
      temperatura: msg.payload.Body.Data.TEMP_POWERSTAGE.Value
    };
    return msg;
  6. Conecta nodos gauge y chart del dashboard para visualizar los datos
  7. Configura un nodo debug para verificar que los datos lleguen correctamente

La API responde en formato JSON con códigos de estado. Valor 0 indica datos válidos. Para múltiples inversores, cambia DeviceId=1 por el ID correspondiente.

Implementación SNMP v3 para Monitoreo de UPS Eaton 9PX con Zabbix 6.x

Configuración completa de monitoreo seguro de UPS Eaton 9PX usando SNMP v3 y Zabbix 6.x con OIDs específicos

El monitoreo de UPS críticos requiere protocolos seguros y confiables. SNMP v3 con Eaton 9PX ofrece autenticación SHA-256 y cifrado AES, esencial para infraestructuras empresariales.

Configuración inicial del Eaton 9PX:

  • IP estática: 192.168.1.100/24
  • Usuario SNMP v3: eaton_monitor
  • AuthProtocol: SHA, PrivProtocol: AES
  • Puerto: 161

Los OIDs críticos para monitoreo son:

  • Estado batería: 1.3.6.1.4.1.534.1.2.1.0 (1=OK, 2=Low, 3=Depleted)
  • Carga porcentual: 1.3.6.1.4.1.534.1.4.1.0
  • Voltaje entrada: 1.3.6.1.4.1.534.1.3.1.0
  • Tiempo restante batería: 1.3.6.1.4.1.534.1.2.4.0 (minutos)
  • Temperatura: 1.3.6.1.4.1.534.1.6.1.0

Template Zabbix 6.x:

- key: snmp.get[1.3.6.1.4.1.534.1.2.1.0] name: 'Eaton UPS Battery Status' type: SNMP_AGENT snmp_version: SNMPv3 snmp3_securityname: eaton_monitor snmp3_authprotocol: SHA256 snmp3_authpassphrase: {$SNMP_AUTH_PASS} snmp3_privprotocol: AES256 snmp3_privpassphrase: {$SNMP_PRIV_PASS} interval: 60s triggers: - name: 'Batería en estado crítico' expression: 'last(/Eaton 9PX/snmp.get[1.3.6.1.4.1.534.1.2.1.0])>1' priority: HIGH

Para implementaciones en Colombia, considere la latencia de red ajustando timeouts a 10s mínimo. Configure alertas por WhatsApp Business API para notificaciones críticas 24/7.

El monitoreo continuo permite detectar degradación de baterías antes de fallas críticas, fundamental para datacenters y aplicaciones industriales.

Monitorear temperatura del cuarto de equipos con DS18B20 + ESP32 + Grafana

Automatiza el monitoreo térmico de infraestructura crítica con alertas en tiempo real y históricos visuales

Este sistema permite vigilar continuamente la temperatura del datacenter para prevenir fallas por sobrecalentamiento.

  1. Conecta el sensor DS18B20 al ESP32: VCC a 3V3, GND a GND, DATA a GPIO4 con resistencia pull-up 4.7kΩ a VCC
  2. Instala InfluxDB v2.7+ y crea bucket 'datacenter_monitoring' con token de escritura
  3. Programa el ESP32 con este código Arduino:
    #include <OneWire.h>
    #include <DallasTemperature.h>
    #include <WiFi.h>
    #include <InfluxDbClient.h>

    OneWire oneWire(4);
    DallasTemperature sensors(&oneWire);
    InfluxDBClient client("http://192.168.1.100:8086", "datacenter_monitoring", "tu_token");

    void setup() {
    sensors.begin();
    WiFi.begin("tu_ssid", "tu_password");
    }

    void loop() {
    sensors.requestTemperatures();
    float temp = sensors.getTempCByIndex(0);
    Point point("temperatura");
    point.addTag("location", "cuarto_equipos");
    point.addField("value", temp);
    client.writePoint(point);
    delay(30000);
    }
  4. En Grafana, conecta InfluxDB como datasource y crea dashboard con query: from(bucket:"datacenter_monitoring") |> range(start: -1h) |> filter(fn: (r) => r._measurement == "temperatura")
  5. Configura alerta para temperatura > 28°C con notificación Telegram usando webhook de Grafana
