Implementación práctica de Modbus RTU con inversores SMA Sunny Boy en Colombia

Configuración técnica detallada de comunicación Modbus RTU con registros reales y código Python para monitoreo

Los inversores SMA Sunny Boy utilizan protocolo Modbus RTU para comunicación industrial, esencial en proyectos solares colombianos que requieren monitoreo centralizado.

Configuración Hardware:

  • Baudrate: 9600 bps
  • Data bits: 8, Stop bits: 1, Paridad: None
  • Dirección esclavo por defecto: 3
  • Terminación 120Ω en extremos del bus RS485

Registros Modbus críticos:

  • 30775-30776: Potencia AC instantánea (W) - 32-bit unsigned
  • 30513-30514: Tensión DC entrada 1 (mV) - 32-bit unsigned
  • 30517-30518: Corriente DC entrada 1 (mA) - 32-bit unsigned
  • 30805-30806: Energía total generada (Wh) - 32-bit unsigned
  • 30825: Temperatura del inversor (°C) - 16-bit signed
  • 30201: Estado operacional - 16-bit unsigned

Implementación Python:

from pymodbus.client.sync import ModbusSerialClient

client = ModbusSerialClient(method='rtu', port='/dev/ttyUSB0',
baudrate=9600, timeout=3)
client.connect()

# Leer potencia AC (registros 30775-30776)
result = client.read_holding_registers(30775, 2, unit=3)
if not result.isError():
power_ac = (result.registers[0] << 16) + result.registers[1]
print(f"Potencia AC: {power_ac} W")

# Leer temperatura
temp_result = client.read_holding_registers(30825, 1, unit=3)
temp_celsius = temp_result.registers[0] / 100
print(f"Temperatura: {temp_celsius}°C")

client.close()

Consideraciones técnicas: Los registros 32-bit requieren lectura de dos registros consecutivos. El estado operacional (30201) indica: 35=MPP, 381=Apagado, 455=Advertencia. Para instalaciones en altitudes colombianas >2000m, monitorear temperatura constantemente.

Esta implementación permite integración con SCADA locales y cumple normativas CREG para reporte de generación distribuida.

Leer SOC y tensión de batería Pylontech desde Node-RED con modbus-serial

Monitorea en tiempo real el estado de carga y voltaje de baterías Pylontech US3000C para sistemas solares híbridos

Las baterías Pylontech US3000C/US5000 exponen datos críticos vía Modbus RTU que puedes leer directamente desde Node-RED para monitoreo y automatización.

  1. Instala el nodo node-red-contrib-modbus en tu instancia Node-RED
  2. Conecta cable RS485-USB al puerto Console de la batería Pylontech (pines 7-8, 115200 baud, ID Modbus: 1)
  3. Arrastra nodo Modbus-Read al flow y configura:
    • Server: localhost puerto /dev/ttyUSB0
    • Unit ID: 1
    • Address: 0x1018 (SOC), 0x1014 (voltaje)
    • Quantity: 1 registro cada uno
  4. Añade nodo Function para procesar la respuesta:
// Decodificar registros Pylontech
let soc = msg.payload[0]; // Registro 0x1018
let voltage = msg.payload[0] / 100; // Registro 0x1014 (mV a V)
msg.payload = {
  soc: soc + '%',
  voltage: voltage + 'V',
  timestamp: new Date()
};
return msg;
  1. Programa lectura cada 30 segundos con nodo Inject
  2. Conecta salida a nodo Debug para verificar datos: {"soc":"85%","voltage":"51.2V"}

Resultado: Dashboard en tiempo real del estado de tus baterías Pylontech para optimizar ciclos de carga.

Comunicación Modbus TCP con Inversores Fronius Symo: Guía de Implementación

Implementación práctica de Modbus TCP con inversores Fronius Symo: registros, códigos de función y script Python completo

Los inversores Fronius Symo implementan protocolo Modbus TCP en puerto 502, facilitando la integración con sistemas SCADA y monitoreo remoto. La configuración requiere habilitar Modbus TCP desde el menú de comunicación del inversor.

Registros Modbus críticos:

  • 40070-40071: Potencia AC instantánea (Uint32, W)
  • 40092-40093: Energía total generada (Uint32, Wh)
  • 40101: Voltaje DC String 1 (Uint16, V)
  • 40103: Corriente DC String 1 (Uint16, A)
  • 40108: Temperatura del inversor (Int16, °C)
  • 40118: Estado de operación (Uint16)

El protocolo utiliza función code 04 (Read Input Registers) para lecturas. Los valores requieren factores de escala según especificaciones SunSpec.

Script Python para lectura de registros:

from pymodbus.client.sync import ModbusTcpClient

client = ModbusTcpClient('192.168.1.100', port=502)
client.connect()

# Leer potencia AC (registros 40070-40071)
result = client.read_input_registers(40069, 2, unit=1)
if result.isError():
print('Error en lectura')
else:
power_raw = (result.registers[0] << 16) + result.registers[1]
power_watts = power_raw if power_raw < 2**31 else power_raw - 2**32
print(f'Potencia AC: {power_watts} W')

# Leer temperatura
temp_result = client.read_input_registers(40107, 1, unit=1)
temperature = temp_result.registers[0]
print(f'Temperatura: {temperature/10} °C')

client.close()

Consideraciones técnicas: Verificar timeout de 5 segundos, configurar Unit ID correctamente (generalmente 1), y validar endianness para registros de 32 bits. En instalaciones colombianas, considerar latencia de red en conexiones remotas.

Conectar inversor Victron MultiPlus II a Home Assistant con VenusOS y MQTT

Integra datos en tiempo real de tu inversor Victron MultiPlus II con Home Assistant para monitoreo y control remoto

Configurar la integración MQTT entre tu Victron MultiPlus II y Home Assistant permite monitorear y controlar tu sistema de energía desde un dashboard unificado.

  1. Habilita MQTT en VenusOS: Accede a Settings → Services → MQTT on LAN (SSL) → Enable service. Configura sin autenticación para red local segura.
  2. Anota el Device Instance: Ve a Device List y anota el número de tu MultiPlus II (generalmente 276 para sistema principal).
  3. Configura MQTT broker en HA: Instala Mosquitto broker desde Add-ons Store si no tienes uno configurado.

mqtt:
  sensor:

      unit_of_measurement: "%"
    - name: "Victron AC Load"
      state_topic: "N/48e7da865bc0/vebus/276/Ac/Out/L1/P"
      unit_of_measurement: "W"
  1. Cambia Portal ID: Reemplaza '48e7da865bc0' con tu Portal ID real visible en Settings → VRM online portal → Portal ID.
  2. Reinicia HA: Los sensores aparecerán automáticamente. Crea tarjetas en Lovelace dashboard para visualizar SOC, potencia AC/DC, voltajes y estados del sistema.

Protocolo Modbus TCP/RTU con Inversores Fronius Symo: Guía Implementación

Configuración práctica de registros Modbus para monitoreo de inversores Fronius Symo con códigos Python funcionales

Los inversores Fronius Symo implementan protocolo Modbus TCP (puerto 502) y RTU (RS485) siguiendo estándar SunSpec, facilitando integración en sistemas SCADA colombianos.

Configuración de Registros Principales:

  • 40084-40085: Potencia AC Instantánea (32-bit Float, Factor escala 40086)
  • 40092-40093: Energía Total Generada (32-bit Unsigned, Factor escala 40094)
  • 40196-40197: Tensión DC String 1 (16-bit, Factor escala 40198)
  • 40283: Estado Operacional (16-bit: 1=Off, 2=Sleeping, 3=Starting, 4=MPPT, 5=Throttled)

Implementación Python para Lectura:

from pymodbus.client.sync import ModbusTcpClient

client = ModbusTcpClient('192.168.1.100', port=502)
client.connect()

# Leer potencia AC (registros 40084-40085)
result = client.read_holding_registers(40084, 2, unit=1)
if not result.isError():
# Convertir registros a float32
raw_power = (result.registers[0] << 16) | result.registers[1]
scale_factor = client.read_holding_registers(40086, 1, unit=1).registers[0]
actual_power = raw_power * (10 ** scale_factor)
print(f'Potencia AC: {actual_power} W')

# Leer estado operacional
status = client.read_holding_registers(40283, 1, unit=1).registers[0]
estados = {1:'Apagado', 2:'Standby', 3:'Iniciando', 4:'MPPT', 5:'Limitado'}
print(f'Estado: {estados.get(status, "Desconocido")}')

client.close()

Consideraciones para Despliegue: Configurar timeout mínimo 3 segundos por condiciones de red en Colombia. Validar función code 0x03 (Read Holding Registers) habilitada en configuración Fronius Solar.web. Para instalaciones multi-string, iterar registros 40196+ según cantidad de strings configurados.

Comunicación Modbus TCP con Inversores Fronius Symo: Registros y Configuración

Configuración completa de comunicación Modbus TCP con inversores Fronius Symo, incluyendo registros críticos y código Python

Los inversores Fronius Symo integran comunicación Modbus TCP nativa, facilitando la integración con sistemas SCADA en instalaciones solares comerciales colombianas. La configuración requiere habilitación del protocolo en Fronius Solar.web y configuración de red adecuada.

Configuración de Red:

  • Puerto TCP: 502 (estándar Modbus)
  • Unit ID: 1 (configurable vía interfaz web)
  • Timeout: 5000ms recomendado
  • IP estática obligatoria para monitoreo confiable

Registros Modbus Críticos:

  • 40084-40085: Potencia AC Total (32-bit, Factor: 1W)
  • 40092-40093: Corriente AC Total (32-bit, Factor: 0.01A)
  • 40098-40099: Tensión AC L1-N (32-bit, Factor: 0.01V)
  • 40106-40107: Frecuencia AC (32-bit, Factor: 0.01Hz)
  • 40284-40285: Energía Total DC (32-bit, Factor: 1Wh)
  • 40320: Estado del Inversor (16-bit)

Implementación Python:

from pymodbus.client.sync import ModbusTcpClient

client = ModbusTcpClient('192.168.1.100', port=502)
client.connect()

# Leer potencia AC total (registros 40084-40085)
result = client.read_holding_registers(40084, 2, unit=1)
if result.isError():
print('Error de comunicación')
else:
power_raw = (result.registers[0] << 16) + result.registers[1]
power_w = power_raw if power_raw < 2147483648 else power_raw - 4294967296
print(f'Potencia AC: {power_w}W')

client.close()

La implementación debe considerar valores con signo de 32 bits y manejo de errores de red. Para instalaciones críticas, implementar reconexión automática y logging de fallos de comunicación.

Implementación SNMP v3 para Monitoreo de UPS Eaton 9PX con Zabbix 6.x

Configuración completa de monitoreo seguro de UPS Eaton 9PX usando SNMP v3 y Zabbix 6.x con OIDs específicos

Configuración inicial del Eaton 9PX:

  • IP estática: 192.168.1.100/24
  • Usuario SNMP v3: eaton_monitor
  • AuthProtocol: SHA, PrivProtocol: AES
  • Puerto: 161

Los OIDs críticos para monitoreo son:

  • Estado batería: 1.3.6.1.4.1.534.1.2.1.0 (1=OK, 2=Low, 3=Depleted)
  • Carga porcentual: 1.3.6.1.4.1.534.1.4.1.0
  • Voltaje entrada: 1.3.6.1.4.1.534.1.3.1.0
  • Tiempo restante batería: 1.3.6.1.4.1.534.1.2.4.0 (minutos)
  • Temperatura: 1.3.6.1.4.1.534.1.6.1.0

Template Zabbix 6.x:

- key: snmp.get[1.3.6.1.4.1.534.1.2.1.0] name: 'Eaton UPS Battery Status' type: SNMP_AGENT snmp_version: SNMPv3 snmp3_securityname: eaton_monitor snmp3_authprotocol: SHA256 snmp3_authpassphrase: {$SNMP_AUTH_PASS} snmp3_privprotocol: AES256 snmp3_privpassphrase: {$SNMP_PRIV_PASS} interval: 60s triggers: - name: 'Batería en estado crítico' expression: 'last(/Eaton 9PX/snmp.get[1.3.6.1.4.1.534.1.2.1.0])>1' priority: HIGH

Monitorear temperatura del cuarto de equipos con DS18B20 + ESP32 + Grafana

Automatiza el monitoreo térmico de infraestructura crítica con alertas en tiempo real y históricos visuales

Este sistema permite vigilar continuamente la temperatura del datacenter para prevenir fallas por sobrecalentamiento.

  1. Conecta el sensor DS18B20 al ESP32: VCC a 3V3, GND a GND, DATA a GPIO4 con resistencia pull-up 4.7kΩ a VCC
  2. Instala InfluxDB v2.7+ y crea bucket 'datacenter_monitoring' con token de escritura
  3. Programa el ESP32 con este código Arduino:
    #include <OneWire.h>
    #include <DallasTemperature.h>
    #include <WiFi.h>
    #include <InfluxDbClient.h>

    OneWire oneWire(4);
    DallasTemperature sensors(&oneWire);
    InfluxDBClient client("http://192.168.1.100:8086", "datacenter_monitoring", "tu_token");

    void setup() {
    sensors.begin();
    WiFi.begin("tu_ssid", "tu_password");
    }

    void loop() {
    sensors.requestTemperatures();
    float temp = sensors.getTempCByIndex(0);
    Point point("temperatura");
    point.addTag("location", "cuarto_equipos");
    point.addField("value", temp);
    client.writePoint(point);
    delay(30000);
    }
  4. En Grafana, conecta InfluxDB como datasource y crea dashboard con query: from(bucket:"datacenter_monitoring") |> range(start: -1h) |> filter(fn: (r) => r._measurement == "temperatura")
  5. Configura alerta para temperatura > 28°C con notificación Telegram usando webhook de Grafana
